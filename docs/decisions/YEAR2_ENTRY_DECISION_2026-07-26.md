## 1. 背景

首年路线图（Micro、A1-A6、B1-B6、C1-C6、D0-D3）全部完成并发布。当前实现为无模型、零依赖、仅合成数据的确定性骨架。进入 Year 2 前，五个产品分岔必须由产品负责人裁决；本文件记录裁决结果。本决定只授权起草 PRDv06 与后续门禁流程，不授权任何业务编码。

## 2. 决定内容

### 2.1 模型接入方式

1. 定义可插拔 Model Capability 接口，模型只能 propose：模型输出永远只是 ChangeSet 候选，不得直接写 Canonical，不得自动升格 Fact，不得绕过用户确认（PRD §6.1、§11.4 已有语义不变）。
2. 本地模型优先：支持用户自备的本地 OpenAI 兼容端点（如 Ollama、llama.cpp），仅允许 `127.0.0.1`/localhost HTTP 调用，继续零第三方依赖（stdlib HTTP 客户端）。不随产品捆绑任何模型权重。
3. 云端 API 为可选后端：默认禁用；启用须用户按舱室 + 目的显式授权，授权有范围和到期（PRD §17.4 语义延伸）。
4. 红线舱室 `health`、`finance`、`relationship`、`sealed` 的内容永远只许本地模型处理，云端后端必须 fail closed 拒绝。
5. 模型、prompt、embedding、reranker 版本全部进审计记录（PRD §22.4 既有要求），升级走既有模型升级门禁。

### 2.2 首个连接器

选择**本地文件夹文本导入**（`.txt`/`.md` 日记与笔记批量导入，可选轮询监视新增文件）作为 FR-302 的第一个连接器切片：完全确定性解析、零第三方依赖、格式公开可长期读取、与既有 Source Vault + CoverageWindow 语义直接对接。微信导出、ICS 日历等其余连接器的优先级保持 `DQ-008` deferred，不在本决定裁决。

### 2.3 真实数据红线

1. 真实个人数据默认永不出本机；唯一例外是 §2.1.3 的显式授权云端后端，且红线舱室无例外。
2. 仓库、fixture、测试、CI、演示永远只使用显式合成数据（既有不可违反项不变）。
3. 真实数据模式对用户开放的前置条件：完成"真实数据生产合同"——删除、封存、备份、导出、恢复、升级语义达到与合成演示相同的验证标准，且全部为真实执行记录。
4. 已发布的 `v0.2.0-beta` 保持"仅合成演示"标注不变；真实数据能力不得靠更新说明追认，只能靠新版本发布。

### 2.4 界面形态

本地 Web UI：Python stdlib HTTP 服务绑定 `127.0.0.1`，完全离线，无账户、无云服务、无第三方依赖、无前端构建链（vanilla HTML/JS），作为 A5 应用壳的呈现扩展，复用既有 CLI/核心能力，不新增业务语义。CLI 继续维护。原生桌面/移动框架与任何依赖引入后置，需要时另立 ADR。

### 2.5 MCP 开放时机

MCP runtime 排在真实数据链路（Y2-S1/S2）与本地 Web UI（Y2-S3）verified 之后；进入 MCP 切片前重开 `DQ-013`，未裁决时维持最保守拒绝。S8 合同保持 Approved 图纸状态，不提前实现。

### 2.6 Year 2 切片排序

| 切片 | 内容 | 关键约束 |
|---|---|---|
| `Y2-S1` | 真实文件夹文本导入链路（Source Vault 批量/监视导入 + CoverageWindow + 真实数据生产合同） | 确定性、零依赖、无模型 |
| `Y2-S2` | Model Capability 接口 + 本地模型解释器（从真实 Source 生成 propose-only 候选） | localhost only、红线舱室 enforcement、版本审计 |
| `Y2-S3` | 本地 Web UI（记录、审查、确认、视图、撤销、导出） | stdlib、127.0.0.1、离线 |
| `Y2-S4` | 云端模型可选后端（默认禁用 + 舱室授权 + 红线 fail closed） | 显式授权、可审计 |
| `Y2-S5` | MCP runtime 最小子集 | 先重开 DQ-013 |

`Y2-S1` 与 `Y2-S2` 同属"真实数据首链路"里程碑，但分别走独立门禁与 recovery point。

### 2.7 PRDv06 授权

授权起草 `PRDv06.md`，范围仅限把 §2.1-§2.6 的语义并入产品基线：真实数据生产合同、模型接入政策、FR-302 首个连接器激活、本地 Web UI 呈现扩展、MCP 门禁时机与 Year 2 切片入口。32 条 FR 编号与优先级不变；Year 2 其余非目标（同步、数字遗产、A2A、家庭授权）保持关闭。v0.5 发布后转只读历史基线；S1-S9 须逐份完成兼容复核后才可开切片的 SPEC applicability review。

## 3. 非目标

- 多设备加密同步（`DQ-007` deferred）、家庭授权与数字遗产（`DQ-009`）、A2A（`DQ-010`）。
- 微信/日历/邮件等其余连接器（`DQ-008` 未裁决部分）。
- 扩大预授权自动处理范围（`DQ-011` deferred；模型候选不改变 §11.4 边界）。
- 云端模型默认开启、真实数据上传、账户体系、任何新第三方运行时依赖。
- 修改任何已 verified 首年切片的 fixture/oracle/结果或业务代码语义。

## 4. 不变量

- `Y2E-INV-001`：模型输出永远只是候选；无用户确认的模型结果不得进入 Canonical。
- `Y2E-INV-002`：红线舱室内容不得离开本机；云端后端对红线舱室 fail closed。
- `Y2E-INV-003`：真实数据模式开放前必须完成真实数据生产合同的真实执行验证。
- `Y2E-INV-004`：仓库与测试永远不引入真实个人数据；合成 fixture 边界不随真实数据能力松动。
- `Y2E-INV-005`：核心包继续零第三方依赖；任何依赖引入须独立 ADR 与产品决定。
- `Y2E-INV-006`：未运行的测试继续记 `not_executed`；新切片同样走完整门禁链，不因 Year 2 提速。
