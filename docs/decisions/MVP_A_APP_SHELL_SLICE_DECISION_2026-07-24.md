## 1. 决定内容

选择 MVP-A 的 A5 作为下一条窄切片：只证明一个固定合成用户可以通过单一本地入口完成完整操作旅程——记录合成文本、以自然语言审查候选与影响预览、确认发布、读取更新后的 Core View、获取回执、查看历史并撤销——全程不要求理解 ChangeSet 内部结构。

顺序理由：按路线图 MVP-A 顺序 A1→A5；A1-A4 的核心行为均已 verified 并有 recovery point；A5 是把已验证核心组装为可用产品形态的最后一块，其后的 A6 硬化依赖一个真实可用的壳。

## 2. 产品依据

- PRD §20 FR-001：接收文本与第三方规范输入包。
- PRD §20 FR-005：提供自然语言审查和高级影响预览。
- PRD §20 FR-006：发布后更新或失效 Core View。
- PRD §20 FR-007：提供 ChangeSet 回执、历史和撤销。
- PRD §10 原则 2：用户拥有最终裁决权——所有规范写入经用户确认。
- PRD §10 原则 5：可纠正性——用户必须能够纠正、撤销。
- PRD §26 验收：普通用户路径不要求手工安装数据库或理解内部结构。

## 3. 切片范围

- 单一固定合成 profile `a5_app_shell_v1`：一段合成文本输入走完完整用户旅程的各步骤，每步有固定合成预期结果。
- 应用壳单一入口：记录、审查、确认、读取、回执、历史、撤销全部通过同一本地入口可达；入口形态（CLI/TUI/最小本地 UI）由本切片 ADR 决定，不在本决定预选。
- 自然语言审查：候选与影响预览以自然语言呈现，附证据引用；不暴露 ChangeSet JSON 给普通用户路径。
- 旅程语义复用已验证核心：intake（FR-001）、candidate（FR-003/B1）、ChangeSet 发布（FR-004）、Core View 更新（FR-006/A2）、回执与撤销（FR-007/Micro）；本切片只做可用性组装与缺口补齐，不重写核心语义。

## 4. 非目标

- 营销首页、云账户、多租户、在线强依赖、移动应用。
- 通用 NLP、真实输入渠道、连接器、多设备同步。
- 权限策略编辑器、Grant 管理 UI（A4 之后的独立切片）。
- 真实个人数据。

## 5. 不变量

- 应用壳的每个写操作仍然全部经过 ChangeSet；壳不提供绕过审查的"快速写入"。
- 自然语言呈现不得改变底层语义；预览内容与发布结果一致或显式标记差异。
- 撤销后所有 Core View 恢复一致（复用 Micro 已验证语义）。
- 默认离线可用；壳的任何网络能力需独立授权（本切片无网络能力）。
- trust、closeness、人格判断不因壳操作被自动修改。

## 6. 授权与下一步

本决定只授权 S1/S3/S5/S6/S7 的 A5 applicability review、追踪和测试合同设计。完成这些开发前产物前不得编写 A5 业务代码。无新重开的 deferred question。
